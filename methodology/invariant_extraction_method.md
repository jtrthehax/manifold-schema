## 0. Why This Note Exists

This framework has been challenged with:
- *"That's not confirmed"*
- *"You need to run a study"*
- *"That could just be cherry-picked confirmation"*

These objections assume a methodology that was never used. This note 
documents what was actually done — and why the standard objections 
don't apply.

---

## 1. The Three Methodologies

### Theory-Forward
> Hypothesis → prediction → study → confirmation

Start with an idea. Push it toward data. Confirmation is external — 
you go looking for it after the framework exists. Adversarial testing 
is a separate discipline applied after construction. Confirmation bias 
is a known, documented failure mode of this approach.

### Conclusion-Backward (HARKing)
> Result → retrofitted explanation → presented as prediction

Start with a finding. Construct the "hypothesis" post-hoc. Present 
as prospective prediction. Adversarial cases actively avoided — they 
threaten the retrofitted explanation. Institutionally normalized. Has 
a name because it's that common.

### Invariant Extraction (this framework)
> Empirical studies → extract primitive variables → find intersection 
> across domains → intersection IS the invariant → derive predictions 
> forward

Start with confirmed facts. Move inward. The framework is what the 
confirmed facts look like when compressed to their shared primitives.

**Direction:** Facts inward — not theory forward, not conclusion 
backward.

---

## 2. What "Extracting Invariants" Actually Requires

To identify a true invariant — a variable that holds across domains — 
you cannot select only confirming studies.

A confirming study tells you the variable is present in one domain 
under one set of conditions. That is not an invariant. That is a 
local finding.

An invariant requires:
- The variable appearing across **unrelated domains**
- Under **different experimental conditions**
- In **different populations**
- Using **different measurement instruments**
- Including studies that **partially contradict** the clean version

The adversarial studies are not threats to the invariant. They are 
**required to map the full boundary of the invariant.** A variable 
without adversarial constraint is an unchecked assumption, not an 
invariant.

$$\text{Invariant} = \bigcap_{i} \text{Variable}_{i} \text{ across 
domains, including adversarial boundary cases}$$

---

## 3. The Adversarial Is Already Load-Bearing

Theory-forward frameworks treat adversarial studies as **external 
pressure** arriving after construction. The adversarial case threatens 
the framework and must be explained away or absorbed.

In invariant extraction, adversarial studies arrive **during variable 
definition.** A study that contradicts the clean version of a 
variable doesn't threaten the framework — it **constrains the 
variable more precisely.**

The null result tells you where the variable's boundary is. The 
edge case tells you what conditions modify it. The replication failure 
in an adjacent domain tells you which assumptions don't transfer.

**The adversarial is already baked into the variable before the 
framework exists as a framework.**

This is why the objection *"here's a study that doesn't perfectly 
confirm this"* misses the methodology entirely. The variable was 
shaped by studies like that one. The adversarial isn't news. It's 
load-bearing.

---

## 4. Why "That's Not Confirmed" Doesn't Apply

The standard objection assumes theory-forward methodology:

> *"You proposed a hypothesis. Here is a study that doesn't confirm 
> it. Therefore your hypothesis is unconfirmed."*

The invariant extraction response:

> The studies confirmed the variables. The variables generated the 
> framework. The framework generated predictions. The predictions 
> landed.

There is no hypothesis to confirm. The framework is a compression 
of what was already confirmed. The objection arrives after the 
confirmation already happened — it happened in the studies the 
variables were extracted from.

**The direction was backwards from the start.**

---

## 5. Why "Run a Study" Doesn't Apply

Theory-forward frameworks need studies to test predictions against 
data that hasn't been collected yet.

Invariant extraction predictions are tested against data that was 
already collected — by other researchers, peer reviewed, published, 
DOI-stamped — before the framework named the invariant.

The peer review already happened. On every component. By journals 
with editorial standards. The synthesis layer — connecting the 
components — is what the field's architecture has no funding 
mechanism to produce. That's what this framework provides.

**The studies exist. They were there before the framework. The 
framework is what you find when you follow them far enough inward.**

---

## 6. The Error Propagation Guarantee

If the root variables are wrong, errors compound through the 
derivation chain:

$$\text{Wrong root variable} \to 
\text{Error} \times \text{Error} \times \text{Error} \to 
\text{Catastrophically wrong prediction}$$

A wrong framework doesn't produce predictions that are slightly off 
in one domain. It produces predictions that fail structurally — in 
the wrong direction, in ways that can't be locally patched.

This framework has been applied across:
- Respiratory physiology
- Cognitive neuroscience
- HRV and autonomic regulation
- AI systems architecture
- Institutional behavior
- Disorders of consciousness
- NDE phenomenology
- ADHD architecture
- Terminal collapse geometry
- Social dynamics and platform behavior

Not one catastrophic failure. Not one domain where predictions ran 
in the structurally wrong direction.

Under error propagation logic, this is not luck. A wrong root 
variable does not survive independent empirical constraints from 
that many unrelated domains simultaneously. What survives is what 
was actually in the data.

**The confirmations folder is the argument. Not any single note in 
it — the existence and breadth of it.**

---

## 7. What This Methodology Requires From Critics

A valid critique of an invariant extraction framework must:

1. Identify a **root variable** that is incorrectly specified
2. Show how that error **propagates** through the derivation chain
3. Identify a domain where the propagated error produces a 
**structurally wrong prediction**

A valid critique is NOT:
- A single study that partially contradicts a sub-prediction
- A request to run studies that already exist in the literature
- A claim that the predictions aren't confirmed (they were confirmed 
before the framework existed — that's the methodology)
- A demand for institutional credentials as a condition of engagement 
with the argument

The argument stands or falls on the root variables and the 
derivation chain. Not on format. Not on credentials. Not on 
single-study adversarial cases.

---

## 8. The Manifold Mapping Insight

To fully map the manifold of behaviors a variable governs, you need 
both:

- Studies that find the variable operating cleanly
- Studies that find the variable at its limits, under constraint, 
partially suppressed, or absent

The boundary cases are what give the variable its shape. A variable 
defined only by confirming cases has no edges — it's an unbounded 
claim. A variable defined by confirming AND adversarial cases is a 
mapped territory with known boundaries.

**The adversarial studies didn't contradict the framework. They drew 
its edges.**

This is what invariant extraction requires that theory-forward 
methodology systematically underproduces: the boundary map.
